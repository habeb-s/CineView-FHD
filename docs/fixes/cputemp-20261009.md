# CineView FHD 2.3.5 — receiver temperature fix (2026-10-09)

## Environment
- Reported on: Octagon SF8008 4K Supreme (machinebuild `sf8008`, HiSilicon Hi3798MV200), OpenATV 7.6.0
  (build 20260821), Python 3.13.12, armv7l.
- Regression receiver: Vu+ Duo 4K SE, OpenATV 8.0.1 (build 20261008), Python 3.14.7.
- Both receivers run CineView MLA as their active skin; it was not replaced or modified for this work.

## Root cause
The `CPU: xx°C` label (InfoBar and Second InfoBar, `<convert type="CineViewCPUTemp">Short</convert>`,
position 1077,1030, size 132×28, Regular;18) is produced by `Components/Converter/CineViewCPUTemp.py`.
2.3.4 shipped three variants of it:

| Carrier | Variant | SF8008 result |
|---|---|---|
| OpenATV snapshot `openatv-final-20260926`, OpenATV 2.3.4 ipk, OpenViX snapshot `openvix-final-20260923` | reads only `thermal_zone0`, `/proc/stb/sensors/temp0/value`, `/proc/stb/fp/temp_sensor` | `CPU: --°C` (none exists) |
| OpenBH snapshot `openbh-final-20260923`, OpenBH 2.3.4 ipk | also lists `/proc/hisi/msp/pm_cpu`, but parses the first word as a number | `CPU: --°C` (`float("CPU:")` fails) |
| OpenViX 2.3.4 ipk | `CineViewHardware.cpu_temperature()` | works on SF8008; fails on `pm_temp`-only and thermal_zone1-only layouts; Fahrenheit shown as °C |

On the SF8008 the driver reports the temperature only in `/proc/hisi/msp/pm_cpu`:

```
CPU: freq = 1600000(kHz), current volt = 1190(mv)
CPU: AVS = On, hpm offset = 0 hpm target = 0x153
Tsensor: temperature = 45 degree
CPU: Temp Control is Quit
```

## Fix
One converter for all images: `components/Converter/CineViewCPUTemp.py` (same reading logic as CineView MLA 1.0.2,
which was verified in the GUI on the SF8008). Every source is optional and probed by existence; nothing is assumed
about a model or brand:
1. the three original paths in their original order — receivers that worked keep the same reading;
2. other kernel thermal zones (cpu/soc first);
3. `/proc/stb/sensors/temp/value`, `/proc/stb/fp/temp_sensor_avs`;
4. HiSilicon `/proc/hisi/msp/pm_cpu`, `/proc/hisi/msp/pm_temp` (`temperature = <n>`).

Only plausible values (0 < t < 150 °C, millidegrees and Fahrenheit converted) are shown; otherwise `CPU: N/A`,
never 0 or an invented value. Polled every 5 s while the label is shown (unchanged). The skin XML, sizes and
positions are unchanged.

## Distribution
- Release `v2.3.5`: the three 2.3.4 packages with only `CineViewCPUTemp.py` replaced and the version strings
  bumped (control, postinst banner, CineView Control `VERSION` / footer / updater `PLUGIN_VERSION`). Built by
  `tools/build_2.3.5.py`, checked by `tools/verify_2.3.5.py` (same 403/426/438 entries and modes; exactly 5 files
  differ). All three are gzip packages.
- `update.json` → 2.3.5, so CineView Control → BLUE (Online Update) offers it to 2.3.4 users.
- `install.sh` (= `install-cineview-smart.sh`): after the pinned image snapshot, installs the 2.3.5 layer —
  CineView Control and the fixed converter — from the SHA256-pinned 2.3.5 package. The pinned snapshots themselves
  are not modified.
- `updater/CineViewUpdater/plugin.py` in the repository is intentionally left at 2.3.4: a change to it triggers
  `.github/workflows/build-cineview-2.3.4.yml`, which rebuilds and re-uploads the v2.3.4 assets with `--clobber`
  and would overwrite the rollback packages. The 2.3.5 packages carry `PLUGIN_VERSION = "2.3.5"`.

### Additional finding (fixed in 2.3.5)
The 2.3.4 OpenATV package was zstd-compressed (`data.tar.zst`). `install.sh` unpacks the update package with
`dpkg-deb`, or `ar` + `tar` when dpkg-deb is missing. On the SF8008 (OpenATV 7.6.0) there is no dpkg-deb and
GNU tar has no zstd binary: `tar (child): zstd: Cannot exec` — the smart installer would stop with
"Unable to extract update data" on OpenATV. The 2.3.5 OpenATV package is gzip; unpacking it with the receiver's
own `ar` + `tar` was verified on the SF8008.

  The 2.3.4 zstd package fails there (`zstd: Cannot exec`).

## Rollback
- Receiver: `opkg install --force-reinstall --force-downgrade` the 2.3.4 package from release `v2.3.4`
  (unchanged), or restore `/tmp/cineview-before-*.tar.gz` written by the installer.
- Repository: revert the 2.3.5 commits on `main`; `update.json` then points to 2.3.4 again.
