# Issue #8 — OpenBH smart install, recording-safe restarts, release workflow (2026-10-09)

Completion state: **RUNTIME TESTED** (simulation, containers, read-only checks on two OpenATV receivers).
Not DEVICE VERIFIED on OpenBH — see "Needs a real OpenBH receiver".

## 1. OpenBH smart install
**Root cause.** `install-openbh-live.sh` was pinned (f1a6b09) to the OpenBH snapshot of commit 9397853, which was
rebuilt from the OpenBH ipk contents and lost three components of the previous pinned snapshot 26d1390:
`CineViewMoviePath.py`, `LukaPosterXEMC.py` and the persistent-cache `CineViewPosterX.py`. The installer requires
all three, so it stopped with `required file missing: .../LukaPosterXEMC.py`. The OpenBH `MovieSelection` screen that
`openbh_compat.py` injects still uses `LukaPosterXEMC` (poster) and `CineViewMoviePath` (FILE / PATH lines); OpenBH's
skin loader (`skin.py`, `except SkinError`) skips such widgets, so OpenBH package users had the PVR screen without
them. The 2.3.4 / 2.3.5 OpenBH packages lack the same three files.

**Fix.**
- `snapshots/openbh-final-20261009/` = 9397853 (all 436 entries unchanged, incl. the Plugin Browser / EPG fixes)
  + the three files from 26d1390 (438 entries), built reproducibly by `tools/build_openbh_snapshot.py`
  (SHA256 `b27edd0f…feede`, commit 1bd5d01). The 26d1390 `CineViewPosterX.py` is the 9397853 file plus the
  persistent cache functions — nothing else differs.
- `install-openbh-live.sh` pinned to it. Its own checks are unchanged.
- The three files live in `components/openbh/` and are also in the OpenBH 2.3.6 package (online updater path).

## 2. Recording-safe restarts
`packaging/recording_guard.sh` defines `cv_recording_active` (POSIX / BusyBox): a recording is assumed while
OpenWebif `/api/statusinfo` reports `"isRecording": "true"`, or while the `enigma2` process holds a `*.ts` file
(not timeshift) open for writing (`/proc/<pid>/fdinfo` access mode). `tools/sync_recording_guard.py` keeps one
identical copy in every script that restarts Enigma2:

| Script | While recording |
|---|---|
| `install.sh` (= `install-cineview-smart.sh`) | installs, does not restart, prints a warning |
| `install-openatv-live.sh`, `install-openvix-live.sh`, `install-openbh-live.sh` (stand-alone use) | same |
| package `postinst` (`packaging/postinst.in`) | does not restart; with `CINEVIEW_NO_RESTART=1` never restarts |
| online updater (`updater/CineViewUpdater/plugin.py`) | runs `CINEVIEW_NO_RESTART=1 opkg install …`; restarts only when `RecordTimer.isRecording()` / `nav.getRecordings()` report no recording, re-checked just before `quitMainloop(3)`; no automatic restart when it cannot be checked |
| `activate-installed-safe.sh` | refuses before changing anything |
| `recover-openatv8.sh` | keeps the safe skin setting, does not restart |

The `postinst` also keeps the installers' rollback backups `/tmp/cineview-before-*` (it used to delete every
`/tmp/cineview-*` file).

## 3. Release workflow
`.github/workflows/build-cineview-2.3.4.yml` (rebuilt "2.3.4" from 2.3.3 inputs on every updater change and uploaded
with `--clobber` into v2.3.4) is replaced by `.github/workflows/build-cineview-release.yml`:
- the version is `PLUGIN_VERSION` of `updater/CineViewUpdater/plugin.py`;
- if `v<version>` is not published: build it from the base release in `packaging/release.json`
  (`tools/build_release.py`), verify (`tools/verify_release.py`), publish with `gh release create` — never `--clobber`;
- if `v<version>` is published: nothing is rebuilt or uploaded; the published packages are checked against the
  source and the run fails when the source changed without a new `PLUGIN_VERSION`;
- static checks and the unit tests run first.
